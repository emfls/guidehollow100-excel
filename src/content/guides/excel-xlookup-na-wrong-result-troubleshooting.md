> **읽기 전 참고** Microsoft 공식 XLOOKUP·#N/A 오류 설명을 바탕으로 작성했습니다. 예제는 독자가 재현할 수 있도록 설계한 예상 결과이며 실제 고객사의 Excel 데이터를 검증했다는 뜻은 아닙니다.

## XLOOKUP 오류, 가장 먼저 확인할 4가지

엑셀에서 XLOOKUP 함수가 #N/A를 반환하거나 엉뚱한 값이 나오면 **조회 ID의 존재 여부, 텍스트·숫자 자료형, 두 범위의 행 정렬, 중복 ID**부터 확인하세요. #NAME?이 표시된다면 함수 철자 및 Excel 버전부터 점검합니다.

값을 못 찾는 상황을 무조건 0으로 바꾸는 것은 위험합니다. 특히 가격·재고·회계 자료에서 **미등록 값과 실제 0**은 전혀 다른 의미이기 때문입니다.

## 정상 수식과 인수의 의미

A열에 상품 코드가 있고 C열에 가격, E2에 찾을 코드가 있다면 다음 수식을 사용합니다.

```javascript
=XLOOKUP(E2,$A$2:$A$100,$C$2:$C$100,"찾을 수 없음",0)
```

| 인수 | 값 | 설명 |
| --- | --- | --- |
| 조회값 | E2 | 조회할 상품 코드 |
| 조회배열 | A2:A100 | 코드를 검색할 범위 |
| 반환배열 | C2:C100 | 같은 행의 값을 가져올 범위 |
| 찾지 못했을 때 | "찾을 수 없음" | 값이 없을 때 표시하는 문구 |
| 일치 모드 | 0 | 정확히 일치하는 값만 검색 |

Microsoft가 안내하는 전체 구문은 다음과 같습니다.

```javascript
=XLOOKUP(lookup_value,lookup_array,return_array,[if_not_found],[match_mode],[search_mode])
```

XLOOKUP은 기본적으로 정확히 일치하는 값을 찾습니다. 조회할 값이 없다면 일반적으로 #N/A 오류가 나지만, 네 번째 인수를 지정하면 오류 대신 지정된 문구가 표시됩니다. 문구가 보인다고 조회 실패 원인이 해결된 것은 아닙니다.

## 증상별 빠른 진단표

| 발생한 문제 | 우선 의심할 원인 | 첫 점검 |
| --- | --- | --- |
| #N/A | 없는 ID, 공백, 형식 불일치 | 원본 ID 및 자료형 확인 |
| #NAME? | 함수명 오류 또는 미지원 Excel 버전 | XLOOKUP 철자와 버전 확인 |
| #VALUE! | 잘못된 인수·범위 크기 | 조회·반환배열 점검 |
| 오류는 없지만 값이 다름 | 중복 ID, 행이 밀린 범위 | 원본 행·중복 확인 |
| 빈칸이나 0 표시 | 실제 원본 값, 오류 대체값 | 일치한 원본 셀 열기 |
| 정렬 순서에 따라 값이 달라짐 | 이진 검색 모드 | 기본 검색 모드로 비교 |

이 표는 가능한 원인을 좁히기 위한 출발점입니다. 하나의 오류 코드가 모든 상황에서 같은 원인을 의미하지는 않습니다.

## 1. 찾으려는 코드가 실제로 있는지 확인

다음 수식으로 E2의 상품 코드가 조회 범위에 몇 번 나타나는지 살펴봅니다.

```javascript
=COUNTIF($A$2:$A$100,E2)
```

0이면 COUNTIF의 비교 규칙에서 일치하는 값이 없다는 의미입니다. 2 이상이라면 중복이 있을 수 있습니다.

단, COUNTIF에는 와일드카드 문자와 자체적인 비교 규칙이 있습니다. 별표 또는 물음표를 실제 코드의 일부로 사용하는 경우에는 COUNTIF 결과만으로 문자열이 완전히 똑같다고 판단하면 안 됩니다. 실제 셀 내용을 추가로 검사하세요.

## 2. 숫자처럼 보이는 텍스트를 구분

외부 프로그램이나 CSV에서 불러온 값은 숫자로 보이더라도 텍스트로 저장돼 있을 수 있습니다. 다음 함수를 이용해 형식을 확인합니다.

```javascript
=ISTEXT(E2)
=ISNUMBER(E2)
=ISTEXT(A2)
=ISNUMBER(A2)
```

특히 **00127**처럼 앞자리 0이 의미 있는 상품·고객·송장 ID를 숫자로 바꾸면 127로 변환되어 원래 코드와 달라질 수 있습니다.

실무에서는 원본 열을 곧바로 변환하지 말고 **보조 열을 만들어 형식을 정규화한 뒤** 예상 결과를 시험하는 것이 안전합니다. 셀 표시 서식을 바꾼다고 저장된 텍스트 값이 반드시 숫자로 바뀌는 것도 아닙니다.

## 3. 숨은 공백과 외부 데이터 오류 정리

상품 ID 뒤에 공백이 있으면 눈으로 보기엔 같아도 정확히 일치하지 않을 수 있습니다. 보조 열에서 먼저 비교합니다.

```txt
=TRIM(A2)
```

웹에서 복사한 데이터에는 일반 공백이 아닌 줄 바꿈 없는 공백(문자 코드 160)이 포함되기도 합니다. 이 경우에는 다음 방법을 검사할 수 있습니다.

```javascript
=TRIM(SUBSTITUTE(A2,CHAR(160)," "))
```

하지만 코드 중간의 공백이 의미 있는 상품 체계도 있습니다. 원본 데이터를 덮어쓰기 전에 정상화해도 되는 식별자인지 확인하세요.

## 4. 조회배열과 반환배열의 시작 행을 맞추기

정상적인 수식은 조회배열과 반환배열이 같은 원본 행을 가리키도록 지정되어야 합니다.

**정상 예시**

```txt
=XLOOKUP(E2,$A$2:$A$100,$C$2:$C$100,"찾을 수 없음",0)
```

**잘못 대응된 범위 예시**

```txt
=XLOOKUP(E2,$A$2:$A$100,$C$3:$C$101,"찾을 수 없음",0)
```

두 범위의 길이가 같더라도 반환 범위가 한 행 아래에서 시작하면 다른 상품의 가격이 반환될 수 있습니다. 이 경우 오류 코드가 아니라 **그럴듯한 잘못된 숫자**가 표시될 수 있어 더 주의해야 합니다.

원본에서 조회한 ID와 반환된 가격이 실제로 같은 행에 있는지 직접 대조합니다.

## 5. 중복 ID와 첫 번째·마지막 검색

XLOOKUP은 기본 설정에서 첫 번째 일치 항목부터 검색합니다. 동일한 상품 코드가 여러 행에 있으면 첫 번째 값을 반환합니다.

```javascript
=COUNTIF($A$2:$A$100,E2)
```

중복이 있고 마지막으로 등장하는 값을 찾는 것이 업무상 맞는 규칙이라면 검색 모드 -1을 사용할 수 있습니다.

```javascript
=XLOOKUP(E2,$A$2:$A$100,$C$2:$C$100,"찾을 수 없음",0,-1)
```

이 수식은 **마지막 일치 행**을 찾을 뿐, 날짜가 가장 최근인 거래를 자동 선택하지는 않습니다. 최신 가격이 필요하다면 원본이 날짜순으로 정확히 정렬됐는지, 어떤 날짜를 적용하는지 확인해야 합니다.

## 6. 이진 검색 모드의 정렬 조건

여섯 번째 인수의 검색 모드에 2 또는 -2를 사용하면 이진 검색을 수행합니다. Microsoft 문서에 따르면 이 방식은 조회배열이 지정된 순서로 정렬돼 있어야 하며, 그렇지 않으면 잘못된 결과가 나올 수 있습니다.

오류를 확인할 때는 먼저 기본 검색 모드로 되돌려 정확히 일치하는 값을 확인합니다.

```javascript
=XLOOKUP(E2,$A$2:$A$100,$C$2:$C$100,"찾을 수 없음",0)
```

정렬 상태를 보장할 수 없는 업무용 데이터에는 이진 검색을 무작정 적용하지 마세요.

## 7. Excel 버전과 수식 구분자 확인

#NAME?은 함수명을 인식하지 못할 때 발생할 수 있습니다. Microsoft는 **Excel 2016과 Excel 2019에서 XLOOKUP을 사용할 수 없다고 명시**합니다. 새 버전에서 작성한 파일을 구버전에서 열면 함수가 정상 동작하지 않을 수 있습니다.

일부 국가·지역 설정에서는 함수 인수 구분자로 쉼표가 아니라 세미콜론을 사용하기도 합니다. 다른 사람의 예제를 복사했는데 구문 오류가 나는 경우 현재 Excel 환경의 구분자 설정도 확인하세요.

## 5행 예제로 직접 결과 검증하기

실무 파일에 적용하기 전에 작은 표로 수식의 작동 원리를 확인하세요.

| 행 | A열: 상품 코드 | B열: 설명 | C열: 가격 |
| --- | --- | --- | --- |
| 2 | P-101 | 볼펜 첫 번째 기록 | 25 |
| 3 | P-102 | 노트 | 40 |
| 4 | P-101 | 볼펜 두 번째 기록 | 29 |
| 5 | 00127 | 라벨(텍스트 ID) | 18 |
| 6 | P-103 | 무료 샘플 | 0 |

A5의 00127은 **텍스트 형식**으로 입력하세요. 앞자리 0이 사라지면 예제가 달라집니다.

E2에 P-101을 넣고 F2에 다음 수식을 입력합니다.

```javascript
=XLOOKUP(E2,$A$2:$A$6,$C$2:$C$6,"찾을 수 없음",0)
```

예상 결과는 **25**입니다. 첫 번째 P-101에 해당하기 때문입니다. 다음 상황도 시험할 수 있습니다.

- E2에 P-999를 입력하면 수식의 네 번째 인수 때문에 **찾을 수 없음**이 표시됩니다.
- E2에 텍스트 00127을 입력하면 예상 결과는 **18**입니다.
- E2에 P-103을 입력하면 예상 결과는 **0**입니다. 이는 실제 가격 0이지 누락값이 아닙니다.
- E2에 P-101을 입력하고 검색 모드 -1을 쓰면 두 번째 P-101의 가격 **29**가 예상됩니다.

```javascript
=XLOOKUP(E2,$A$2:$A$6,$C$2:$C$6,"찾을 수 없음",0,-1)
```

이 수치는 예제 표에서 계산될 **예상 결과**입니다. 실제 사용 중인 Excel 파일을 직접 실행했다는 의미는 아닙니다.

## IFERROR로 잘못된 데이터를 가리지 않기

모든 XLOOKUP 오류를 0으로 바꾸면 조회 결과가 없는 상품과 실제 가격이 0인 상품이 구분되지 않습니다. 가능하면 XLOOKUP의 네 번째 인수를 이용해 일치하는 값이 없을 때만 메시지를 표시하세요.

```javascript
=XLOOKUP(E2,$A$2:$A$100,$C$2:$C$100,"미등록 ID",0)
```

미등록이라는 상태가 사업상 '0원'이라는 뜻은 아닙니다. 원본 오류를 일괄 변환하기 전에 데이터 품질을 확인하는 것이 우선입니다.

## 실무 적용 전 확인 체크리스트

- [ ] 원본 Excel·CSV 파일을 백업했다.
- [ ] 조회 ID가 원본에 있는지 확인했다.
- [ ] 숫자·텍스트 형식과 앞자리 0 보존 여부를 점검했다.
- [ ] 숨은 공백과 특수 문자를 확인했다.
- [ ] 조회배열과 반환배열의 행이 일치한다.
- [ ] 중복 ID가 있다면 어떤 기록을 사용할지 업무 규칙을 정했다.
- [ ] 정렬되지 않은 데이터에는 이진 검색을 사용하지 않았다.
- [ ] 실제 0, 빈칸, 미등록, 함수 오류를 구분했다.
- [ ] 정상 ID·미등록 ID·중복 ID·텍스트 ID를 각각 시험했다.
- [ ] 파일을 공유할 사용자의 Excel 버전을 확인했다.

## 자주 묻는 질문

### XLOOKUP에서 #N/A가 나타나는 이유는 무엇인가요?

정확히 일치하는 값을 찾지 못했을 가능성이 큽니다. 조회값이 원본에 없을 수도 있고 저장 형식이나 공백 때문에 달라진 값으로 인식될 수도 있습니다. 네 번째 인수에 메시지를 넣으면 해당 메시지가 대신 표시됩니다.

### 오류는 안 나는데 엉뚱한 결과가 나옵니다.

반환배열의 시작 행이 밀려 있거나 중복 ID 중 첫 번째 행을 가져오고 있을 수 있습니다. 이진 검색 모드와 정렬 상태도 확인하세요.

### 가장 최근 가격을 찾으려면 역방향 검색만 사용하면 되나요?

아닙니다. -1은 마지막 일치 행을 찾는 기능이며 최신 날짜를 판별하지는 않습니다. 최신 기록인지 결정하는 사업 규칙이 따로 필요합니다.

### Excel 2019에서 XLOOKUP을 사용할 수 있나요?

Microsoft 지원 문서 기준 Excel 2019 및 2016에서는 XLOOKUP을 사용할 수 없습니다. 최신 Excel에서 만든 문서를 열더라도 계산 호환성이 보장되지 않습니다.
